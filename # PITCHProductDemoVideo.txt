# KEVexploit — Product Demo Video (2:00)

| Time | On screen | Voice-over |
|---|---|---|
| **0:00–0:10** | KEVexploit logo. Show a project with multiple dependencies and vulnerability alerts appearing. | “Software projects depend on hundreds of external packages. But when vulnerabilities are discovered, developers face a difficult question: which ones should they actually fix first?” |
| **0:10–0:23** | Open the Repository Scanner. Show a `package-lock.json` or `requirements.txt` being submitted. | “That's why we built KEVexploit. Our main product is a Repository Scanner that analyzes a project's actual dependencies and helps developers identify which vulnerabilities deserve attention first.” |
| **0:23–0:38** | Show scanning process, OSV.dev lookup, advisory-to-CVE mapping. | “It reads pinned package versions, checks them against OSV, maps security advisories to CVEs, and enriches each finding with EPSS, known exploited status, and available public exploit intelligence.” |
| **0:38–0:53** | Show ranked scan results. Open a finding and highlight its evidence. | “Instead of returning another long list of vulnerabilities, it prioritizes findings using multiple signals. Developers can inspect the evidence behind each result and understand why one vulnerability may deserve attention before another.” |
| **0:53–1:07** | Transition to historical analysis. Show the 58% statistic prominently, then exploit-signal examples. | “Our historical analysis revealed an important limitation in public threat intelligence: approximately 58% of positive cases had no public exploit indicator in the data available to us. Relying on public exploit records alone can leave important risks undetected.” |
| **1:07–1:22** | Breach Radar. Animate 72,670 CVEs narrowing to Top 500. | “To address this, we built a broader vulnerability intelligence pipeline. We analyzed 72,670 CVEs from the 2026 competition dataset and selected a Top 500 shortlist — less than 0.7% of the original dataset.” |
| **1:22–1:42** | Architecture animation: Granite 4.2 30B, XGBoost, Logistic Regression, Granite 4.2 8B LoRA, rank ensemble. | “Our approach combines large language models with carefully validated classical machine learning. IBM Granite 4.2 30B extracts structured vulnerability intelligence, while Granite 4.2 8B with LoRA contributes to our ensemble alongside XGBoost and regularized Logistic Regression. We combine their rankings to capture different types of evidence.” |
| **1:42–1:52** | Show equal-weight rank averaging, diversity cap, and a CVE dossier. | “We then apply evidence-based filters and diversity controls, while keeping the ranking explainable so analysts can investigate the reasoning behind each prediction.” |
| **1:52–2:00** | Return to Repository Scanner. Show final results, then logo and `kevexploit.us`. | “KEVexploit brings vulnerability intelligence closer to the code developers actually run. Less time sorting alerts. More focus on the risks that matter. KEVexploit.” |
